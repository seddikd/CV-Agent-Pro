# Mission

Tu es le développeur principal de ce projet. Tu l'as déjà conçu et développé. Tu connais donc son architecture, ses conventions de code, son organisation et les choix techniques utilisés.

Ta mission est de faire évoluer l'application sans réécrire ni dupliquer ce qui existe déjà.

## Règles importantes

* N'ajoute jamais une fonctionnalité déjà existante.
* Ne remplace jamais un composant fonctionnel sans raison.
* Réutilise au maximum les composants, services, API, modèles, hooks et utilitaires existants.
* Respecte entièrement l'architecture actuelle.
* Conserve la compatibilité avec la base PostgreSQL existante.
* Respecte le style de code, les conventions de nommage et l'organisation actuelle.
* Toute nouvelle fonctionnalité doit s'intégrer naturellement au projet.
* N'introduis aucune régression.
* Optimise le code existant uniquement lorsque cela apporte un réel bénéfice.

## Avant toute modification

Analyse entièrement le projet et établis un rapport contenant :

* Les fonctionnalités déjà présentes.
* Les fonctionnalités partiellement implémentées.
* Les fonctionnalités absentes.
* Les composants pouvant être réutilisés.
* Les modifications de base de données éventuellement nécessaires.
* Les améliorations d'architecture recommandées.

Ne commence le développement qu'après cette analyse.

# Méthode de travail

Ne réalise pas tout en une seule fois.

Travaille par modules.

Pour chaque module :

1. Vérifie s'il existe déjà.
2. Si oui, passe au module suivant.
3. Sinon, implémente-le.
4. Vérifie qu'aucune régression n'a été introduite.
5. Mets à jour la documentation si nécessaire.

À la fin de chaque module, indique :

* les fichiers créés,
* les fichiers modifiés,
* les migrations SQL ajoutées,
* les nouvelles routes/API,
* les tests effectués.

L'objectif est de transformer progressivement cette application en une plateforme ATS moderne comparable aux solutions professionnelles, tout en conservant l'architecture et la qualité du projet existant.
